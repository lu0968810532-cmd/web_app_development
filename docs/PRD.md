# 產品需求文件 (PRD) - 食譜收藏夾

## 1. 專案概述
- **專案名稱**：食譜收藏夾
- **專案描述**：本系統為一桌面端應用程式（或本地運行之 Web 端），旨在協助用戶數位化儲存、分類與檢索個人食譜。用戶可以紀錄食材清單、烹飪步驟及心得，並透過圖形化介面快速查找想做的料理，取代傳統雜亂的紙本筆記。
- **背景與動機**：現代人常從網路或書籍收集食譜，但紙本筆記容易散落遺失，手機截圖則難以系統化搜尋。為此打造專屬的數位食譜收藏庫，解決管理上的痛點。
- **目標用戶**：
  1. **家庭主夫/主婦**：需管理日常大量菜單的人。
  2. **廚藝初學者**：需要紀錄學習心得與精確食材比例的人（例如：環工系同學實驗之餘的烹飪愛好）。
  3. **美食收藏家**：喜歡從網路上摘錄食譜並加入個人修正的用戶。
- **核心價值主張**：提供直覺的操作介面、穩定的資料庫查詢與隨機探索樂趣，讓下廚不再煩惱吃什麼與怎麼做。

## 2. 功能需求

以下為系統核心功能的說明與使用者故事（User Stories）：

### 1. 食譜新增/編輯介面
**作為** 喜歡紀錄與修正食譜的使用者，
**我希望** 能有一個結構簡單清晰的新增/編輯表單，
**以便** 我可以詳細輸入名稱、食材清單、烹飪步驟與個人心得。

### 2. 圖片匯入與顯示
**作為** 美食收藏家，
**我希望** 能在每篇食譜附加與顯示完成品的照片，
**以便** 視覺化我的成果，並在翻閱想做的料理時更有動力。

### 3. 關鍵字快速搜尋
**作為** 家庭主夫/主婦，
**我希望** 能輸入食材（例如：「番茄」）或菜名進行快速搜尋，
**以便** 利用冰箱現有食材，立刻找到今晚可以烹煮的料理。

### 4. 收藏/標籤分類管理
**作為** 廚藝初學者，
**我希望** 能將食譜以自訂標籤（如：中式、甜點、減脂）歸類並設為最愛，
**以便** 管理不斷擴增的筆記庫，有系統地檢索不同分類。

### 5. 隨請使用 /implementation skill 的「步驟四」，實作 app/templates/ 裡的 HTML 模板。
**作為** 不知道下一餐要吃什麼的人，
**我希望** 系統能夠從我的收藏或特定標籤中隨機推薦一道食譜，
**以便** 幫我解決「今晚吃什麼」的選擇障礙。

## 3. 非功能需求
- **技術限制**：
  - 核心框架：基於預設架構採用 Flask + Jinja2 提供 Web 介面與後端邏輯。
  - 資料庫：採用 SQLite，不僅符合單機需求，也方便讓使用者將資料庫檔案直接在不同裝置中複製備份。
  - （註：為了實現「桌面端感受」，未來亦可考慮將 Flask Server 結合 PyWebView 或類似套件打包為可執行檔。）
- **效能與安全考量**：
  - 需確保圖片上傳時具備壓縮或大小限制，避免應用程式資料夾過度肥大。
  - 資料庫的新增與查詢需防範基本的 SQL Injection（建議搭配 SQLAlchemy 等 ORM 或 Parameterized Query）。

## 4. MVP 範圍 (最小可行性產品)
- **Must Have (必須要有)**：
  - 食譜標題、食材、步驟、心得的新增/編輯/刪除 (CRUD) 基本介面。
  - 可以透過關鍵字進行快速搜尋。
  - 基本的收藏（加入最愛）或標籤分類。
- **Should Have (最好要有)**：
  - 本機圖片上傳與預覽顯示功能。
  - 隨機選餐功能。
- **Nice to Have (有會更好)**：
  - 從網址自動爬蟲匯入食譜內容功能。
  - 食譜匯出/備份機制（匯出為 JSON 或 CSV）。
  - 對應人數倍增或減少的食材份量自動換算。
